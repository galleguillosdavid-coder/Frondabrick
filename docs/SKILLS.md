## 1. Regla Canónica de Estructura (Sección 20)
Para optimizar el consumo de la ventana de contexto de Antigravity (Progressive Disclosure), el archivo `SKILL.md` debe mantenerse estricta y exclusivamente bajo los siguientes 6 encabezados:
1. `## PROPÓSITO`
2. `## CUÁNDO USAR`
3. `## CUÁNDO NO USAR`
4. `## PROCEDIMIENTO`
5. `## REGLAS CRÍTICAS`
6. `## REFERENCIAS`

El contenido extenso, manuales o guías de soporte deben residir en `references/`.

## 2. Habilidades Base del Arnés

| Skill | Nombre | Propósito Principal |
| :--- | :--- | :--- |
| **Planner** | `fronda-planner` | Especificación previa al desarrollo estructurada en 10 secciones obligatorias. Prohibido programar. |
| **Reviewer** | `fronda-reviewer` | Auditoría de código, diffs, pruebas y seguridad en modo estrictamente de solo lectura. |
| **Shield** | `fronda-shield` | Intercepción de seguridad, catálogo de patrones destructivos y 5 niveles de defensa. |
| **TDD** | `fronda-tdd` | Metodología Red-Green-Refactor obligatoria antes de implementar código productivo. |
| **Build** | `fronda-build` | Protocolos de compilación, type-checking y resolución limpia de dependencias. |
| **Memory** | `fronda-memory` | Ciclo de persistencia de lecciones aprendidas bajo el esquema de 8 campos. |
